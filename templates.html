Popup templates — style guide

All seven templates (§5) rendered through the real SDK — same tokens.css, same theme classes, same legal fail-safe (§11.3.3) — not hand-drawn mockups. See the interactive harness for triggered, full-viewport behaviour.

Preview theme

banner — promotional, top

Full-width bar · legal.mode: auto · theme orange

Announcements/promo use (§5, row 1). Position is top or bottom; legal slot appears inline, right-aligned into the flex row on wide viewports.

banner — operational notice

Bottom position · legal.mode: off (not a financial promotion) · theme white-black

Same template, no legal slot — off mode requires a stated reason and is audit-logged (§11.3.1).

modal — centred, no media

Heading + body + CTA · theme black

Promo offers use (§5, row 2). Below 768px this widens edge-to-edge (bottom sheet when actually triggered).

modal — square shape

shape: 'square' · theme white · real logo, adaptive to theme

Same modal builder, square aspect ratio (§4.7.2 "square or portrait formats"). Logo/heading/subhead stay grouped near the top; CTA and the legal slot are pinned to the bottom edge, matching the brand's own layout examples. The logo's wordmark uses currentColor so it reads correctly on any Libertex theme — it's suppressed entirely on LBX themes (below) since no real LBX logo asset exists yet.

modal_media — with image panel

16:9 desktop / 4:3 mobile media slot · theme white · has a mobile content override

Visual campaigns (§5, row 3). Image is object-fit:cover in a fixed-ratio slot so an unexpected source size can't break layout (§5.2).

modal_form — registration, via the real llLanding widget

email / password (+ phone if the domain registry says so) · theme offwhite-orange · consent text with real links resolved from the registry, not typed content (§9.4)

Registration form (§9, rewritten from what this page originally assumed). The fields, consent wording, and submission are all owned by an embedded third-party widget already live on production Libertex domains — this platform never sees the submitted values. This preview loads mock-landing-api.js, not the real widget — same call shape (llLanding.create({ form, apiKey, registrationCallback })), zero network calls, so trying it here never touches anything real. Submitting fires this platform's own form_submit stat and a Tealium utag.view() push, exactly like production. Tab through it — the form fields live in light DOM, not the shadow tree (§9.5), the one deliberate exception in this whole SDK, so the widget's own document.querySelector can find and bind to it.

modal_form_media — registration, with an image panel

Same llLanding-embedded form as modal_form · theme white · 16:9 desktop / 4:3 mobile media slot above the heading

Mirrors modal_media's relationship to modal: identical content schema to modal_form, one field added (image_url/image_alt). Same registration widget, same fail-safe (no registration_domains entry for the host ⇒ suppressed), just with a hero image above the heading.

questionnaire — button-only answers

1–3 questions, one at a time · theme white-black · no free-text input exists (§5.4)

Preference capture / segmentation (§5, row 5). Every tap is a complete, final answer — fires questionnaire_answer immediately, no submit step. Try answering both questions.

gamification — Market Prediction Challenge

Pick an asset, predict higher/lower · theme black-orange · simulated close, not a live quote (§5.5)

Engagement/incentive campaigns (§5, row 6). Pick Gold, EUR/USD, or Bitcoin, call higher or lower, wait out the countdown — the reveal hands off to the same CTA affordance as modal. The price shown is content-supplied, not a real feed; the disclaimer stays on screen throughout, not just as a footnote.

modal — LBX brand

Same template as above · theme lbx-blue · LBX's real palette, not Libertex's (§4.2)

Every template accepts any theme — this is the identical modal builder, just themed lbx-blue instead of a Libertex pairing. Colours are sourced from lbx.com's own CSS (--brand-primary: #012AFF) and rendered "Trade Now" button (black), not invented. Legal is off here only because this gallery runs on localhost, which isn't mapped to the lbx entity — on lbx.com itself, auto mode would resolve LBX's real risk warning exactly as it does for Libertex domains.

How to read this page. Each card is rendered in normal page flow via window.LxPopup.renderInline() — a preview-only API that reuses the exact same content builders and theme/legal resolution as a real triggered popup, just without the fixed-position overlay. Resize the browser below 768px and each modal widens edge-to-edge with only its top corners rounded — the same CSS rule that turns it into a bottom sheet when actually triggered (§5.3); the "sticks to the bottom of the viewport" part only shows up with the fixed overlay show() uses, not in this static, side-by-side layout. See the interactive harness for that. The legal line at the bottom of each promotional template resolves from the registry for this host, exactly as it would for a visitor — it is not typed content. Every template accepts any theme — the last card demonstrates this with the same modal builder used above it, just themed for LBX (a sibling brand, separate palette) instead of Libertex. Use the Preview theme toggle, top right, to force every card to the same light or dark background — useful for checking the logo or legibility without hunting for the one card that already happens to use that background.
